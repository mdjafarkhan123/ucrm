# Design, build, and verify

Read when the active part needs a visual decision, implementation, or proof. First verify its scope and
approval under the parent workflow; use the relevant subject skills rather than loading a whole library.

## Design

Reuse applicable approved examples. When the experience is unsettled, show the smallest useful prototype
or mockup of the main journey and important states on its relevant devices. Use available project guidance
or a suitable tool; the campaign works without a design skill or a required design app. Prototype guidance
is useful when trying a state model or interaction is more informative than discussing it.

Record what Jafar approves, the example's exact location, and what remains undecided. Feed changed behavior
back into the product plan. A visual approval covers what was shown, not unshown workflows or every screen.
Further detail can be designed per part; an unresolved visual choice blocks only dependent work.

## Build and verify

Before substantial implementation, use Proven Development and the project skills relevant to this part's
subject and risk. Inspect existing components and modules. Save the current technical approach, invariants,
failure behavior, and verification in the part note or a linked implementation plan. Record lasting choices
and rationale in ADRs only when warranted. Keep routine technical decisions with the AI.

Build one coherent part, including the failure cases the approved behavior requires. Check the actual
journey against the plan and run meaningful project checks. User-facing behavior needs its main journey
tried in the live app; documentation or skill work needs a realistic use or fresh-session trial instead of
an irrelevant browser test. Use proportional checks for small changes and the project's specialist gates
for higher-risk work. A prototype proves only its stated question.

Keep a short proof pointer: what was checked, where its evidence lives, and any remaining limitation.
Record built-but-unverified work as unfinished. If verification exposes a new product question, research it
and seek only that decision; proceed with independent authorized work. Before finishing or handing over,
read [handover.md](handover.md).

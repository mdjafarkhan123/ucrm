# `/jafar` sales booking: Zoom and Google Meet links (7 October 2026)

Planning evidence from provider documentation and the current repository. “Phone” below means a normal call arranged by Jafar, not a dial-in number for a video meeting.

## What the providers support

| Provider | One new link per booked sales call | Connection needed | Important behavior |
| --- | --- | --- | --- |
| Google Meet through Calendar | Insert a Calendar event with `conferenceData.createRequest`, a new `requestId`, and `conferenceDataVersion=1`. Google explicitly recommends a unique conference for each event to avoid access and privacy problems. Conference creation may initially be `pending`; use the completed video entry point when confirming the booking. [Create events](https://developers.google.com/workspace/calendar/api/guides/create-events), [event resource](https://developers.google.com/workspace/calendar/api/v3/reference/events) | Jafar authorizes access to a writable Google Calendar through OAuth. The API has event write scopes; a public app using certain scopes may need Google's verification. [Calendar scopes](https://developers.google.com/workspace/calendar/api/auth) | A Calendar event and Meet link are created together. The app must keep the event ID to change or cancel it later. Guest update emails can be controlled by `sendUpdates`. [Events insert](https://developers.google.com/workspace/calendar/api/v3/reference/events/insert), [events update](https://developers.google.com/workspace/calendar/api/v3/reference/events/update) |
| Google Meet directly | `POST /v2/spaces` returns a new space and its `meetingUri`. This makes a link without creating a Calendar event. [Create space](https://developers.google.com/workspace/meet/api/reference/rest/v2/spaces/create), [space overview](https://developers.google.com/workspace/meet/api/guides/meeting-spaces-overview) | Jafar authorizes the Meet REST API with Google user OAuth and `meetings.space.created`; that API uses user authentication. [Meet authorization](https://developers.google.com/workspace/meet/api/guides/authenticate-authorize) | The space is persistent, so create a fresh one for each booking. Calendar availability, event invites, and time changes would still need separate handling. [Space overview](https://developers.google.com/workspace/meet/api/guides/meeting-spaces-overview), [space resource](https://developers.google.com/workspace/meet/api/reference/rest/v2/spaces) |
| Zoom | `POST /users/{userId}/meetings` creates a scheduled meeting (`type=2`) and returns its meeting ID and `join_url`. For a user-managed app, `me` can be used as the user ID. Save the participant `join_url`, not the host `start_url`, for customers. [Meetings API](https://developers.zoom.us/docs/api/meetings/), [create-meeting workflow](https://developers.zoom.us/docs/isv/workflows/create-meeting/) | Jafar authorizes a Zoom user-managed OAuth app with meeting write permission; Zoom also offers account-level and server-to-server app types for other ownership models. [OAuth apps](https://developers.zoom.us/docs/integrations/), [creating an OAuth app](https://developers.zoom.us/docs/integrations/create/), [end-user authorization](https://developers.zoom.us/docs/integrations/end-user-auth/) | Zoom documents a 100-create-requests-per-day limit per meeting host. Its host `start_url` expires after two hours for regular users, so it must be fetched again when needed; the participant `join_url` serves a different purpose. [Meetings API](https://developers.zoom.us/docs/api/meetings/) |

## Existing UCRM foundation and gap

- Client onboarding training accepts a manually pasted HTTPS Meet or Zoom URL and a confirmed time; it does not create a provider meeting (`src/lib/server/validation/setup.schema.ts`, `src/routes/api/jafar/organizations/[organizationId]/setup/training/booking/+server.ts`, `src/lib/components/jafar/organization/TrainingHandoverPanel.svelte`).
- No Zoom/Meet OAuth connection or automatic conference creator was found under `src/lib/server` or `src/routes/api/jafar`. The booking-settings research also found no `/jafar` public sales booking page yet. [Booking settings research](jafar-booking-settings-patterns-2026-10-07.md)
- The existing training URL field proves that storing and displaying a supplied link is possible, but it is not the booking integration needed for automatic one-link-per-call creation.

## Product decision supported by this evidence

Let Jafar set each meeting type to **phone**, **Google Meet**, or **Zoom**. A phone booking shows the agreed number/call instructions and creates no video link. A video booking creates a fresh provider meeting only after the slot is safely reserved, stores the provider meeting/event ID, and sends the resulting customer join link in its confirmation. If link creation fails, do not tell the visitor the video booking is fully confirmed without a working link. On reschedule or cancellation, update or cancel the external meeting as well as the UCRM booking.

The provider can be chosen later. **Google Calendar + Meet** is the cleanest Google path if Jafar also wants external calendar events and Google Calendar availability. **Meet REST API** is narrower if he only needs a video link. **Zoom** is equally capable of creating a link per call, but does not itself solve external-calendar availability. Connecting a provider, checking outside busy times, and designing the confirmation/retry flow are implementation decisions still to be agreed. These recommendations are inferences from the cited API behavior, not claims that either integration has been built.

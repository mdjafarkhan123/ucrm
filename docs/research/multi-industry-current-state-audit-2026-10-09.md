# Multi-industry foundation: current-state journey audit

**Scope:** P1 planning, 2026-10-09. This is a source-code and contract audit, not a browser or live-service readiness check. “Exists” means the path is implemented in this checkout; it does not mean a new Industry experience is ready to use it.

## Capability disposition

| Existing capability | P1 disposition | Reason |
| --- | --- | --- |
| Organization identity, membership, separate Uplift/team access, audit and Support | **Keep** | Their account and actor boundaries fit one platform. Clinical access requires a later suitability and safety check. |
| Immutable Package editions, commercial agreement and payment record | **Deepen** | Preserve history and manual confirmation; add explicit experience compatibility before publication and assignment. |
| Public Application, corrections and paid provisioning | **Deepen** | Preserve one journey; add supported-business qualification and confirmed experience profile before provisioning. |
| Contractor Setup questions and service filtering | **Make experience-specific** | Contractor questions remain; shared questions can be reused across separately versioned programs. |
| One global, immediately changing Setup catalogue | **Replace** | It contradicts the approved stable version per started business and independent Industry programs. |
| Contractor sidebar, dashboard, Requests, Quotes, Jobs and Visits | **Make experience-specific** | They fit field service; their vocabulary and workflows cannot stand in for appointments or clinical records. |
| Trade text as a proposed industry classifier | **Retire for classification** | Keep it as historical/application and Contractor profile data. The current free text cannot safely decide an experience. |
| Public form availability based only on active account and form publication | **Replace the availability rule** | It does not represent Uplift readiness or customer launch; preserve the form and token infrastructure where suitable. |

## Contradictions and evidence limits

1. **Active versus public launch:** paid provisioning creates an `active` Organization. Public forms can be published for active Organizations before the separate launch mark. Whether current operational practice prevents early publishing was not established by this code audit.
2. **One questionnaire versus approved industry versions:** the current reader always asks for the globally published Setup catalogue; the approved Medspa/Contractor rule freezes the version an Organization started. This is planned, not built.
3. **Package versus experience:** public Packages are filtered by publication/visibility, and effective access resolves Package and member permissions without an experience. Package publication and assignment do not yet prove industry compatibility.
4. **Business identity:** Application `trade` and Organization profile trade exist, but no persistent Industry experience/Business type appears in the generated Organization type or the inspected admission path. P2 must define authoritative history and correction before a backfill is designed.
5. **Proof level:** this audit used repository code and approved contracts only. It did not verify remote database drift, live provider configuration, browser journeys, first-clinic requirements or traffic capacity. The Package Builder and client delivery campaigns also retain their own hands-on proof gates.

## Decisions exposed for P2–P4

- **P2:** Decide which minimal facts the Application needs before Uplift can qualify a business; whether Package selection comes before or after Uplift classification; how unclear and mixed businesses wait; and what a buyer sees while waiting.
- **P2:** Define a named Organization experience profile, its correction/history, and the exact relationship among commercial access, Setup, staff work, operational readiness and each public surface's launch permission.
- **P3:** Define which existing features are genuinely shared, which Package editions can be sold per experience, and how the experience + Package + member permission check is applied to both menu and direct API access.
- **P4:** Inventory live Contractor Organizations and their agreements, Setup progress and public forms before migration. Decide a reversible backfill and connected proof; do not infer historical Business types from trade text.

**Reference method:** The approved [industry-entry research](industry-onboarding-entry-patterns-2026-10-07.md) supports one assisted application and business-specific invitation; the [HighLevel research](highlevel-multi-industry-white-label-architecture-2026-10-08.md) supports reusable common parts with explicit configuration. Boulevard remains the primary Medspa workflow reference in the approved [Medspa contract](../boulevard-product-behavior-contract.md). These public references do not establish that this application's current paths are clinic-ready.

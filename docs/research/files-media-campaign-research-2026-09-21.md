# Files and media campaign: official product research

Researched 2026-09-21 for the files and media campaign. This note separates **documented product facts** from **recommendations for UCRM**. It is not an approved behavior contract or implementation plan. Sources are limited to official Jobber, Housecall Pro, CompanyCam, and OWASP documentation. No live account records were accessed or changed.

## Executive finding

Mature contractor products do not treat every file as a loose attachment. The strongest pattern is:

1. capture the file in the context where work happens;
2. retain its source, client/property/job context, author, and time;
3. aggregate it into a client or project library for retrieval;
4. keep it private by default; and
5. publish a deliberately selected subset through a quote, invoice, report, email, text, portal, or expiring link.

Jobber is the closest workflow reference. CompanyCam adds the strongest job-site photo organization and proof-of-work patterns. Housecall Pro adds a useful explicit attachment-selection and expiring-share-link model.

## Documented facts: Jobber

### Attachment scope and roll-up

- Internal notes and their attachments can exist on clients, requests, quotes, jobs, visits, and invoices. A visit note is stored as a job note, and notes can be linked forward through the workflow: client → request/quote/job/invoice, request → quote/job/invoice, quote → job/invoice, and job → invoice. There is no property note field. [Notes and Attachments](https://help.getjobber.com/en/articles/notes-and-attachments/)
- Jobber's Files and Media Library is a **client-level aggregate**, not the primary authoring surface. It automatically consolidates files from the client's notes and checklists, organizes them by date, and filters by property, workflow source (client, request, quote, job, invoice), file type, and date. Each file retains client, source, added time, address, and uploader metadata. The library itself is view-only, although some other authoring flows can reuse stored files. [Files and Media Library](https://help.getjobber.com/en/articles/files-and-media-library/)
- The library can show property context when a file's source is linked to a property. A client-level file is not implicitly attached to a property. [Files and Media Library](https://help.getjobber.com/en/articles/files-and-media-library/)
- Messages are a separate media source in the documented product. Two-way SMS supports up to 10 images and 1,600 characters while the whole MMS remains below 5 MB; inbound MMS is not supported in Great Britain. Jobber's Files and Media article does not say message media joins the client library, so that linkage must not be assumed. [Two-Way Text Messaging](https://help.getjobber.com/en/articles/two-way-text-messaging/)

### Product, service, and line-item images

- A request line item may have one photo. It can be newly uploaded or reused from stored media, appears beside the item in Client Hub, and stays tethered to the line item when the request converts to a quote or job. [Request Basics](https://help.getjobber.com/en/articles/request-basics/)
- A quote line item may also have one image, either uploaded or reused. A product/service catalog item can hold a default image so future quote items inherit it; editing or deleting the catalog item does not retroactively change lines already on quotes, jobs, or invoices. When a quote converts, the image is visible on the job and visits but read-only there; it must be changed from the quote. In Client Hub it appears as a thumbnail that opens larger. It does not appear in the quote PDF, online-booking service selection, or QuickBooks product sync. The documented quote-line-item limit is 100 MB, with `png`, `img`, `jpg/jpeg`, `gif`, and `bmp` listed. [Products & Services List](https://help.getjobber.com/en/articles/products-services-list/) [Line Item Images on Quotes](https://help.getjobber.com/en/articles/line-item-images-on-quotes/)
- Advanced quote customization separately supports a quote image gallery of up to 10 AVIF, GIF, JPEG, or WEBP images under 25 MB each. Previews are resized to 168×168 and open at full size. This is distinct from the one-image-per-line-item behavior. [Quotes in the Jobber App](https://help.getjobber.com/en/articles/quotes-in-the-jobber-app/)

### Private access and customer-facing visibility

- Note attachments are internal by default. A worker needs note permission and permission for the underlying record; a dedicated Files and Media permission controls access to the aggregate library. Notes permissions range from job-note-only through view/edit/delete all. [Notes and Attachments](https://help.getjobber.com/en/articles/notes-and-attachments/) [User Permissions](https://help.getjobber.com/en/articles/user-permissions/)
- An internal attachment becomes customer-facing only when a user deliberately adds it to an outgoing email. Quote and invoice PDFs are not attached by default; Jobber sends customers to Client Hub, where transactional actions remain available. [Notes and Attachments](https://help.getjobber.com/en/articles/notes-and-attachments/)
- On select plans, invoice-level images and attachments are separate from internal note attachments. They are tied to the invoice, explicitly shown in Client Hub, and appear as named links in the invoice PDF rather than inline media. Adding them directly is documented as web-only. [Notes and Attachments](https://help.getjobber.com/en/articles/notes-and-attachments/) [Invoice Basics](https://help.getjobber.com/en/articles/invoice-basics/)
- Customer-visible request/quote line-item images and advanced quote images are deliberate presentation content, not an automatic exposure of the internal file library. [Request Basics](https://help.getjobber.com/en/articles/request-basics/) [Quotes in the Jobber App](https://help.getjobber.com/en/articles/quotes-in-the-jobber-app/)

### Viewing, ordering, labels, and proof of work

- Jobber opens note images in a full-size gallery with previous/next navigation. Files and Media supports grid/list views, a larger detail view, carousel navigation, and inline PDF preview on web. [Notes and Attachments](https://help.getjobber.com/en/articles/notes-and-attachments/) [Files and Media Library](https://help.getjobber.com/en/articles/files-and-media-library/)
- The library documents chronological organization and filters, but not manual file ordering, captions, tags, folders, before/after pairing, or a canonical cover photo. These are documentation gaps, not proof the capabilities are absent.
- Jobber explicitly frames mobile note media as suitable for before-and-after photos. For structured customer proof, checklists support an image-upload question with up to 10 JPEG/PNG/HEIC images, 50 MB each, plus long answers; the finished checklist can be emailed as a PDF containing the photos and notes. [Notes and Attachments in the Jobber App](https://help.getjobber.com/en/articles/notes-and-attachments-in-the-jobber-app/) [Checklists](https://help.getjobber.com/en/articles/checklists/)

### Limits, mobile capture, edits, deletion, and export

- Jobber's current documentation is inconsistent about general note attachment size: the web-focused article says 500 MB per file, while the mobile article says 750 MB per attachment and 50 attachments per batch. Both list CSV, DOC/DOCX, PDF, TXT, PPT/PPTX, MP4, JPEG, PNG, GIF, WEBP, AVIF, AAC, MP3, and WAV. Email attachments have a separate 10 MB total limit. Treat the 500/750 MB difference as unresolved until live/API verification. [Notes and Attachments](https://help.getjobber.com/en/articles/notes-and-attachments/) [Notes and Attachments in the Jobber App](https://help.getjobber.com/en/articles/notes-and-attachments-in-the-jobber-app/)
- On visits and assessments, a persistent mobile camera action can capture photos/video directly and Jobber creates the contextual note automatically. Offline notes and files wait locally and sync when connectivity returns and the app is open; unsynced work is lost if the user logs out, deletes, force-closes, or updates the app. Photos can optionally also be kept in the device camera roll. [Notes and Attachments in the Jobber App](https://help.getjobber.com/en/articles/notes-and-attachments-in-the-jobber-app/)
- Mobile photo markup includes drawing, shapes, and text. The user can revert to the original before saving; after save, the markup becomes permanent. Jobber does not document retained revisions of that media. Notes show an Edited indicator when their text/content changes. Deleting a note is permanent, and deleting a linked note removes it from every downstream place where it appeared. [Notes and Attachments in the Jobber App](https://help.getjobber.com/en/articles/notes-and-attachments-in-the-jobber-app/) [Notes and Attachments](https://help.getjobber.com/en/articles/notes-and-attachments/)
- Files and Media supports one-at-a-time or bulk download within one client, but not cross-client bulk download. A note with at least five attachments can export those files by emailing a ZIP to the logged-in user. Clients can download quote, invoice, and receipt PDFs from Client Hub. Sent email attachments remain visible in the Client Communications Report, and sent quote/invoice PDFs preserve how the document looked at send time. [Files and Media Library](https://help.getjobber.com/en/articles/files-and-media-library/) [Notes and Attachments](https://help.getjobber.com/en/articles/notes-and-attachments/) [Client Communications Report](https://help.getjobber.com/en/articles/client-communications-report/)

## Documented facts: adjacent products

### CompanyCam: job-site photo organization and proof

- CompanyCam makes the job/project the container: every photo, video, document, and note belongs to a Project and is automatically saved with time and location. It distinguishes Project Labels from photo Tags; a photo can have multiple tags and tag filters work both within one project and across the photo feed. Its own examples include `Before`, `After`, and `Damage`. [Projects Explained](https://help.companycam.com/en/articles/16416068-projects-explained) [Organizing Photos Using Tags](https://help.companycam.com/en/articles/6971244-organizing-photos-using-tags/)
- Reports turn selected job photos into structured proof with titled sections, summaries, photo descriptions/comments, a cover photo, layout controls, and manual reordering. Reports can pull photos from multiple projects and be shared as a link or PDF. [Creating a Report](https://help.companycam.com/en/articles/7048115-creating-a-report)
- Documents can show capture details, photo tags, location, and photo numbers; photos can be dragged within or between photo sections without deleting or resetting them. [Editing Documents](https://help.companycam.com/en/articles/15880536-editing-documents)
- Customer sharing separates a selected static Gallery from a live Project Timeline. A Gallery can expose only chosen photos and optionally details/descriptions; a Timeline automatically shows new project photos unless individual photos are hidden, and the whole Timeline link can be disabled. Gallery links cannot be disabled by the user without contacting support. [Sharing Photos in CompanyCam](https://help.companycam.com/en/articles/6828401-sharing-photos-in-companycam)
- Guest Access is scoped to one project, requires no account, can expire, and lets the owner control whether the guest can view all project photos; guests can upload photos and comment but cannot browse the rest of the account. Collaborators are account-holding partner businesses with broader contribution rights, but reports, documents, files, tags, labels, payments, and project editing remain excluded. [Guests and Collaborators Explained](https://help.companycam.com/en/articles/15525961-guests-and-collaborators-explained)
- Project files accept PDF, DOC/DOCX, XLS/XLSX, CSV, TXT, JPG/JPEG, PNG, and Numbers up to 100 MB. Mobile can scan one or more paper pages into a PDF. [Uploading Files](https://help.companycam.com/en/articles/6828384-uploading-files)
- Deleting photo/video media first moves it to Project Trash. Standard/restricted users can trash only media they uploaded; admins/managers can restore it on web; permanent deletion occurs after 90 days. Duplicating a photo is the documented way to annotate or edit while keeping the original. [Deleting Photos and Videos](https://help.companycam.com/en/articles/6828387-deleting-photos-and-videos) [Restore Items from Project Trash](https://help.companycam.com/en/articles/6971309-restore-items-from-project-trash) [Duplicating a Photo](https://help.companycam.com/en/articles/6828346-duplicating-a-photo)
- Mobile upload has a visible queue, retry actions, background-upload controls, and a save-to-device escape hatch before troubleshooting. [Troubleshooting Photo and Video Upload Issues](https://help.companycam.com/en/articles/6828388-troubleshooting-photo-and-video-upload-issues-in-the-mobile-app)

### Housecall Pro: deliberate sharing and customer delivery

- Attachments live on customers, properties, jobs, and estimates. When sending an invoice or estimate, the user explicitly selects attachments from the current or previous work and from customer/property profiles. Customers receive view/download access in email and on the invoice/estimate preview, while emailed PDFs do not embed those attachments. Printed/downloaded invoice PDFs may optionally embed images only. [Attachments: Send Customers Photos & Documents](https://help.housecallpro.com/en/articles/1079307-attachments-send-customers-photos-documents)
- A shared attachment link can be sent by email or text and expires after seven days; Housecall Pro says it automatically sends a new link if a customer opens an expired one. The same sharing flow exists in the mobile app. [Attachments: Send Customers Photos & Documents](https://help.housecallpro.com/en/articles/1079307-attachments-send-customers-photos-documents)
- Its viewer supports a carousel, download/delete, zoom, and full screen. Mobile photo uploads continue in the background, pause through lost service or app closure, and resume when service/app returns. Mobile PDFs are job-only and capped at 5 MB. Videos longer than one minute are trimmed before upload. [Attachments: Send Customers Photos & Documents](https://help.housecallpro.com/en/articles/1079307-attachments-send-customers-photos-documents) [Capture and Upload Photos & Videos on Mobile](https://help.housecallpro.com/en/articles/10159740-capture-and-upload-photos-videos-on-mobile) [Video Uploads on Mobile](https://help.housecallpro.com/en/articles/11145993-video-uploads-on-mobile)
- Photo Reports provide a branded, customer-facing proof-of-work layer: multiple reports per job, cover photo, titled/described sections, selected attachments, email/SMS delivery, portal access, and PDF export. Reports can be edited and resent; customers see changes only after the updated report is sent. [Photo Report on Jobs](https://help.housecallpro.com/en/articles/14299953-photo-report-on-jobs)

## Security baseline from an official standard

OWASP recommends defense in depth for uploads: business-necessary extension allowlists; server-side size limits; MIME and file-signature validation without trusting the browser's `Content-Type`; application-generated storage names; authorized uploaders; storage on a separate host or outside the web root; anti-malware/sandbox scanning; content disarm and reconstruction where useful for formats such as PDF/DOCX; current parser libraries; and CSRF protection. [OWASP File Upload Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)

For multi-tenant blob storage, OWASP recommends classifying and partitioning objects by tenant scope, authorizing the exact object and operation before serving it or minting a signed URL, and limiting signed URLs to the required object, operation, lifetime, and revocation model. [OWASP Multi-Tenant Security Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Multi_Tenant_Security_Cheat_Sheet.html#file-storage--blob-isolation)

## Recommendations for UCRM (inferences, not documented Jobber behavior)

1. **Use one media record with explicit links, not copied blobs.** Store one tenant-owned asset plus explicit links to client, property, request, quote, job, visit, invoice, message, checklist/report, and catalog/line item as applicable. Preserve original source, uploader, capture/upload time, property/address context, MIME/type, size, checksum, and customer-visibility state. This supports Jobber-like roll-up without losing provenance.
2. **Make the client library an aggregate, not a dumping ground.** Upload from the active workflow record; let client/property/job libraries roll those files up. Filters should include property, source record, media type, date, uploader, and labels. Clicking source should return the user to the actual record.
3. **Keep all operational files private by default.** Customer visibility should be an explicit publication action with a clear preview of exactly what is shared. Distinguish internal attachments, quote/request presentation media, invoice attachments, proof-of-work reports, and message media rather than using one ambiguous `public` toggle.
4. **Use private R2 objects and short-lived authorized access.** Validate tenant and record permission before issuing a narrowly scoped signed upload/download URL. A share record should have selected assets, recipient/channel context, expiry, revocation, and an audit trail. Do not expose stable object URLs.
5. **Quarantine before availability.** Upload into a non-readable pending state, validate extension/MIME/signature/size, scan for malware, generate safe derivatives, then promote to available. Failed or suspicious objects should remain inaccessible with an understandable processing state. Never generate customer links or thumbnails from unapproved originals.
6. **Preserve originals and make edits derivatives.** Markup, rotation, compression, crops, and annotations should create a derivative while keeping the original immutable. Show who created the derivative and when. For customer-issued quotes, invoices, and proof reports, snapshot the selected media/version so later edits do not silently rewrite historical evidence.
7. **Provide recoverable deletion.** Use trash/soft deletion with a retention window, role-gated restore, and audit history. Block or warn when an asset is referenced by an issued document, customer share, or compliance record. Permanent purge should be a separately authorized lifecycle action.
8. **Treat proof of work as a structured output.** Support reusable labels such as Before, After, Damage, Serial/Model, Completed, and Customer-supplied; descriptions/captions; manual ordering; before/after pairing; and branded reports with sections and PDF/link export. Ordinary attachments should remain quick and lightweight.
9. **Design mobile upload for unreliable service.** Capture directly from a visit/job, support multi-select, compression choices, local pending state, background/resumable transfer, retries, duplicate protection, per-file progress, and a clear warning before any action can discard unsynced media. Do not claim offline safety until destructive app lifecycle cases are tested.
10. **Separate thumbnails from originals.** Lists and galleries should use generated thumbnails; the lightbox should progressively load a larger derivative and offer the original only when permitted. Images get gallery/lightbox treatment; PDFs get inline preview where safe; unknown documents get a typed icon and download path rather than browser execution.
11. **Start with a conservative business allowlist.** A sensible first release is JPEG/PNG/HEIC/WEBP images, MP4 video, PDF, DOCX, XLSX, CSV, and TXT, with server-verified types. Add audio or legacy office formats only when a real workflow requires them. Choose limits from measured mobile/network/processing evidence rather than copying competitors' inconsistent limits.
12. **Keep message media provenance.** If an inbound/outbound message attachment joins the client library, retain its message/conversation link and channel limits. Do not silently convert a communication artifact into general-purpose customer-visible media.

## Decisions still requiring product approval or live verification

- Whether UCRM should expose one client-level library, separate client and property libraries, or both views over the same linked assets.
- Which records are valid upload origins in the first release, especially messages and catalog items.
- Whether customer sharing starts with expiring selected-file links only or also includes live job timelines. A live timeline is higher risk because future uploads can become visible automatically.
- Initial upload limits by media type and whether large video belongs in the first release.
- Trash retention length and the special rules for files referenced by issued financial documents or proof reports.
- Whether contractors need formal before/after pairs or whether labels plus ordered report sections cover the real workflow.
- Live-check Jobber's conflicting 500 MB web versus 750 MB mobile note attachment limit, exact attachment deletion impact on the Files and Media aggregate, and whether message attachments ever join that aggregate.
